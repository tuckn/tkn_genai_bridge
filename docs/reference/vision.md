# VLM比較レポート：料理写真とExcel画面

## 概要

**今回の結果からは、普段の写真・画面説明にはGPT-6.1 Sol、細かい文字の転記にはGemini 4 Argon、費用や外部送信を抑えた大分類にはローカルQwenを選ぶ方針を提案します。** Astraへの一律切り替えを勧めるほどの精度差は確認できず、Opus 5.5は写真・画面の要約を確認できたものの、細字の転記は同条件で未評価です。

このレポートは、`examples` の料理写真1枚とExcel画面1枚について、5モデルの認識結果・誤り・時間・費用を整理したものです。全モデルが主要な被写体や画面構成を説明できましたが、食材名、細字、時計、色の意味では誤りや省略がありました。

更新日：**2026-10-31**。Sol 6.1／Argonは10/31、Astra／Qwen／Opusは9/27の実測です。Opusだけは2枚同時の短い説明という別課題です。以下の使い分けは、この少数例からの暫定的な判断であり、モデル全般の順位ではありません。旧GPT-6 Solの結果はSol 6.1へ流用していません。

**追加検証：** [GPT-6.1 Solのeffort比較](vision-sol61-effort.md)では、low／medium／high／xhighを各画像2回ずつ実行しました。日常の説明には**lowを第一候補**にでき、high・xhighで細字の誤読が解消する傾向は確認できませんでした。以下のモデル間の表にあるSol 6.1は、従来のmediumの結果を維持しています。

### 写真についての判断

写真の説明をそのまま記録に残すなら、まずSol 6.1を使う方針です。今回、Sol 6.1とArgonはいずれも料理・器の配置を詳しく説明し、大根おろしを別の料理と誤認しませんでした。Astraも詳しく観察しましたが、Sol 6.1より高い参考費用を払えば必ず認識が改善する、という結果ではありません。Opusは短い説明で主な料理を押さえており、既にClaudeを使っている場合の要約候補になります。

Qwenは「料理の写真」「とんかつ定食」のような分類に役立ちます。一方、「何の食材か」を保存する用途では、大根おろしを白飯、パセリを小松菜とする誤認が問題になります。大分類だけで足りる画像はローカルで処理し、具体的な名称が必要な画像をSol 6.1等へ回す、という分担が適しています。外部送信できない画像はローカルと人の確認で完結させます。

### スクリーンショットについての判断

画面の説明と文字の転記を分けて選びます。「何のアプリで何をしている画面か」ならSol 6.1が基本候補で、短い概要ならOpusにも実績があります。「注記を一字ずつ取り出す」なら、今回の結果ではArgonを先に試す理由があります。ただし、Argonも画面全体では時計や色分けを誤って説明しました。Astra・Sol 6.1も「ぬ」を「む」と読み、Qwenは誤記があっても不確実性を申告しませんでした。

したがって、**モデルの「不明なし」という回答だけで再確認の要否を決めない**方針が必要です。転記した文字を設定値や記録として使う場合は、対象箇所を元画像と照合します。元の文書やセルの文字列を取得できる場合は、それを確認元にする方針を提案します。細字が読みにくければ拡大・切り出しを次の検証候補にできますが、この比較では効果を測っていません。小さい文字や日本語、色・線の違いに限界がある点は、[OpenAIの画像入力の公式説明](https://developers.openai.com/api/docs/guides/images-vision#limitations)でも案内されています。

### クレジットを抑える運用の判断

すべての画像をローカルとクラウドの両方へ送る運用は提案しません。**大分類だけならQwen、詳しい説明が必要なら最初からSol 6.1、細字転記ならArgon**と、必要な出力で振り分けます。追加のモデル呼び出しは、重要な読み違いや説明の不一致を確認するときに限定します。この分担による実クレジットの削減率は未測定です。

費用は[別表](costs.md#vision-costs)にまとめました。Sol 6.1は2枚で$0.117696、Astraは$0.522220という**API単価換算**でした。サブスクリプションの実消費ではなく、Argon・Opusを含む最安モデルの順位は出せません。
